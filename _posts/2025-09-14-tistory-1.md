### part 1. 웹이란?



웹의 정의

동영상이나, 음성 따위의 각종 멀티미디어를 이용하는 인터넷을 이르는 말로, 인터넷 상에서 동작하는 하나의 서비스입니다.

주의해야 할 사항은, 인터넷과 웹이 비슷한 의미로 쓰이지만 사실 인터넷은 컴퓨터 네트워크 망 자체를 의미하며 웹은 인터넷에서 동작하는 하나의 서비스일 뿐이라는 것입니다. 웹은 인터넷에서 작동하는 하나의 서비스를 뜻하는 말이므로 다른 의미를 가진 용어임을 유의하여야 합니다.





웹 서버와 웹 클라이언트

웹 서버란, 웹 콘텐츠를 저장하거나 처리하는 컴퓨터 또는 소프트웨어. 일반적으로 웹 서버가 되는 컴퓨터에 설치되는 소프트웨어를 말합니다. 대표적인 웹 서버로는 아파치(Apache), 엔진엑스(nginx), IIS(Internet Information Services) 등이 있는데, 웹 서버 소프트웨어는 HTTP 프로토콜을 통해 클라이언트(웹 브라우저)의 요청 정보를 받아 처리하고 그 결과를 다시 클라이언트에 보냅니다.



웹 클라이언트(Web Client)란 웹 서버에 요청을 보내고, 그 결과(웹 페이지)를 받아서 사용자에게 보여주는 프로그램입니다. 우리에게 조금 더 친근한 크롬, 사파리, 엣지, 파이어폭스 등이 대표적인 웹 클라이언트라고 볼 수 있습니다.





프론트엔드와 백엔드

다음은, 프론트엔드와 백엔드의 사전적인 정의입니다.



프론트엔드: 웹/앱 개발 결과물에서 사용자에게 보여지는 부분을 의미

백엔드: 프런트 엔드에 서비스를 제공하는 노드나 소프트웨어 프로그램



조금 더 풀어서 정의하자면, 프론트엔드는 직접적으로 사용자에게 보여지는 디자인적인 요소(UI)와 그 UI가 제대로 작동이 되도록 만드는 코드(HTML, CSS, JavaScript 등)입니다.



반면, 백엔드는 사용자가 직접 보지는 못하지만 서비스가 돌아가게 해주는 시스템들을 의미하고 웹/앱에서 발생하는 데이터 저장, 처리, 보안, 서버 통신 같은 일들을 담당합니다. 사용자가 버튼을 눌렀을 때 그 동작 뒤에서 어떰 계산이 일어나고 데이터 베이스에 기록되는지, 서버가 어떻게 응답을 보내는지 같은 것들이 모두 백엔드의 영역입니다.





### part 2. HTTP



HTTP의 의미

웹에 기반을 두고 컴퓨터간에 하이퍼텍스트 문서를 주고받을 수 있도록 TCP 프로토콜위에서 운용되는 프로토콜입니다. 조금 더 쉬운 이해를 위해 말하자면, HyperText Transfer Protocol(하이퍼 텍스트 전송 규약)으로 웹 브라우저(클라이언트)와 웹 서버가 서로 말할 때 쓰는 공통 언어 내지 데이터를 주고 받을 때 쓰는 약속이나 규칙 등이라고 생각하면 됩니다.



방식을 설명해보자면, &lt;s&gt;(정확할지는 모르겠으나...) &lt;/s&gt;

웹 브라우저(클라이언트)가 웹 서버에게 HTTP로 요청을 보냄 - 웹 서버가 요청을 받고 그에 맞는 파일 등을 준비해서 HTTP로 응답 - 웹 브라우저가 그 응답을 해석(번역)해서 사용자에게 보여줌.



이러한 방식입니다.





HTTP 상태 코드

HTTP 응답 상태 코드는 특정 HTTP 요청이 성공적으로 완료되었는지 알려줍니다. 응답은 5개의 그룹으로 나누어집니다. 정보를 제공하는 응답, 성공적인 응답, 리다이렉트, 클라이언트 에러, 그리고 서버 에러가 있습니다.





- 1xx: 정보(Informational)

- 2xx: 성공(Successful)

- 3xx: 리다이렉트(Redirection)

- 4xx: 클라이언트 오류(Client Error)

- 5xx: 서버 오류(Server Error)

ex)

- 200 OK → 요청 성공

- 301 Moved Permanently → 영구적으로 다른 주소로 이동

- 404 Not Found → 요청한 자원이 없음

- 500 Internal Server Error → 서버 내부 오류







HTTP 메소드

HTTP는 요청 메서드를 정의하여, 주어진 리소스에 수행하길 원하는 행동을 나타냅니다. 간혹 요청 메서드를 "HTTP 동사"라고 부르기도 합니다. 각각의 메서드는 서로 다른 의미를 구현하지만, 일부 기능은 메서드 집합 간에 서로 공유하기도 합니다. 이를테면 응답 메서드는 안전하거나, 캐시 가능하거나, 멱등성을 가질 수 있습니다. 쉽게 표현하자면, HTTP라는 공통된 언어 안에서 메서드는 어떤 '동작'을 원하는지를 표현하는 역할을 합니다.



다음은 많이 사용되는 HTTP 메서드를 정리한 것입니다.



GET

GET 메서드는 특정 리소스의 표시를 요청합니다. GET을 사용하는 요청은 오직 데이터를 받기만 합니다.

HEAD

HEAD 메서드는 GET 메서드의 요청과 동일한 응답을 요구하지만, 응답 본문을 포함하지 않습니다.

POST

POST 메서드는 특정 리소스에 엔티티를 제출할 때 쓰입니다. 이는 종종 서버의 상태의 변화나 부작용을 일으킵니다.

PUT

PUT 메서드는 목적 리소스 모든 현재 표시를 요청 payload로 바꿉니다.

DELETR

DELETE 메서드는 특정 리소스를 삭제합니다.



이 중, GET과 POST의 차이를 이야기 해보자면 GET은 서버에서 데이터를 조회해 가져오는 것이고, POST는 서버에 새로운 데이터를 제출하거나 생성하는 역할을 합니다.





### part 2. HTTPS





HTTPS의 의미

HTTPS (HyperText Transfer Protocol Secure)는 HTTP 프로토콜의 암호화된 버전입니다. 이것은 대개 클라이언트와 서버 간의 모든 커뮤니케이션을 암호화 하기 위하여 인증서(SSL 또는 TLS)를 사용합니다. 이 보안 연결은 클라이언트가 민감한 정보를 서버와 안전하게 주고받도록 해줍니다. 예를 들어보면, 금융 활동이나 온라인 쇼핑 등이 있습니다. 조금 더 쉽게 설명해보자면, HTTPS는 HTTP + 암호화를 한 버전으로 웹 브라우저와 서버가 대화할 때 중간에서 보거나 바꿀 수 없도록 보호를 해줍니다. HTTTP는 원래 평문(암호화 X)으로 데이터를 주고 받기 때문에 암호화를 위해 나온 것이 HTTPS입니다. HTTP를 엽서, HTTPS를 봉투에 넣은 편지 등으로 비유해 생각한다면 조금 더 이해하기 쉬울 것입니다.





HTTPS의 특징

HTTPS의 중요한 특징은 HTTP에 SSL/TLS 보안 계층을 추가한 프로토콜로, 암호화, 인증, 무결성을 제공한다는 것입니다. 오늘 날 웹의 사실상 표준으로 자리잡고 있으며, 브라우저도 기본적으로 HTTPS의 연결을 우선시합니다. 사용자가 조금 더 안전하게 서버와 데이터를 주고받을 수 있게 만들어주는 프로토콜입니다.

### part 3. 프록시



사전적 의미

데이터를 가져올 때 해당 사이트에서 바로 자신의 PC로 가져오는 것이 아니라 임시 저장소를 거쳐서 가져오는 것. 프록시를 설정하면 수 초의 빠른 속도를 느낄 수 있습니다. 프록시 서버에는 다수의 사용자들이 들르는 사이트에 대한 데이터가 저장되어 있어 경우에 따라 해당 사이트에 들르지 않고 바로 이 서버에 있는 데이터를 이용하기도 합니다. 하지만 프록시 서버에 문제가 생겼거나 과부화가 걸렸을 경우 오히려 더 느려지는 경우도 있습니다. (사이트 → 프록시 서버 → PC)



네트워크에서의 의미

네트워크에서 프록시는 클라이언트와 서버 사이에 위치하여, 클라이언트의 요청을 대신 전달하고 서버의 응답을 중계하는 중간자 역할을 하는 시스템(서버 또는 소프트웨어)입니다.





프록시 역할과 사용 이유

프록시의 사용 이유를 알기 위해선 프록시의 역할을 알아야 하는데, 프록시는 영어로 Proxy = 대리인, 대신하는 것이라는 뜻을 가지고 있습니다. 프록시의 동작 방식 자체가 클라이언트(예시: 웹 브라우저)가 직접 서버에 요청하지 않고 프록시 서버를 거쳐 보내면, 프록시 서버가 그러한 요청을 받아 서버에게 전달하고, 서버가 응답을 주면 그걸 다시 프록시 서버가 클라이언트에게 전달을 하는 방식입니다.

(클라이언트 ↔ 프록시 ↔ 서버 구조)



이 과정에서 HTTP와 설명이 비슷해 헷갈릴 수 있지만&lt;s&gt;&lt;span style=&quot;color: #9d9d9d;&quot;&gt;(저만 그런 걸 수도 있습니다...)&lt;/span&gt;&lt;/s&gt;, 둘은 완전히 다른 것으로 HTTP는 웹에서 데이터를 주고받기 위한 규칙(프로토콜)이고, 프록시는 클라이언트와 서버 사이에서 동작하는 ‘중간자(서버/소프트웨어)’이다. 프록시는 HTTP 자체는 건드리지 않거나, 일부만 가공해서 전달할 수 있다.



프록시의 사용 이유는 프록시의 다음과 같은 특징들 때문입니다.



- 보안/익명성

- 클라이언트의 실제 IP를 숨기고 프록시 IP로 대신 접속.

- 개인정보 보호, 우회 접속 등에 활용.

- 캐싱(Caching)

- 자주 요청되는 데이터를 프록시 서버가 저장해 두었다가, 서버에 다시 가지 않고 클라이언트에 빠르게 제공.

- 속도 개선 + 서버 부하 감소.

- 필터링/제어

- 기업이나 학교에서 특정 사이트 차단, 트래픽 모니터링 등에 사용.

- 보안 강화

- 방화벽처럼 동작하면서 내부 네트워크를 보호.



### part 4. HTML



HTML이란?

인터넷의 홈페이지 등을 만들기 위한 언어로 HTML으로 만들어진 것을 하이퍼 텍스트라고 하며, 태그라는 명령어를 사용해 다양하게 표현할 수 있고 홈페이지 안의 특정 장소를 클릭하면 관련된 다른 페이지나 다른 홈페이지로 간단하게 이동할 수 있습니다. HTML은 문서의 특정 텍스트 영역이 문단인지 목록인지 표의 일부인지 구분 할 수 있도록 의미를 부여하고, 헤더인지, 콘텐츠 컬럼인지, 네비게이션 메뉴인지 알수 있도록 논리적인 영역으로 구조화 하고, 이미지와 비디오 같은 콘텐츠를 삽입할 수 있게 해주는 요소들로 구성된 지극히 간단한 언어입니다.



정리하자면, HTML은 웹페이지의 구조를 정하는 언어로, 인터넷 문서의 뼈대를 만드는 기본적인 언어입니다.





HTML의 기본적인 태그

- &lt;head&gt; : 문서 정보(제목, 메타데이터, CSS/JS 링크 등)를 담는 부분

- &lt;body&gt; : 실제 화면에 표시되는 콘텐츠 부분

- &lt;a href=&quot;...&quot;&gt; : 하이퍼링크 (다른 페이지로 이동)

- &lt;img src=&quot;...&quot; alt=&quot;...&quot;&gt; : 이미지 삽입

(예시) &lt;img src=&quot;cat.jpg&quot; alt=&quot;귀여운 고양이&quot;&gt;

&lt;hr contenteditable=&quot;false&quot; data-ke-type=&quot;horizontalRule&quot; data-ke-style=&quot;style6&quot;&gt;&lt;/hr&gt;



목록

- &lt;ul&gt; : 순서 없는 목록 (bullet point)

- &lt;ol&gt; : 순서 있는 목록 (번호 매김)

- <li> : 목록 항목

&lt;hr contenteditable=&quot;false&quot; data-ke-type=&quot;horizontalRule&quot; data-ke-style=&quot;style6&quot;&gt;&lt;/hr&gt;

표

- <table> : 표 전체

- <tr> : 표의 행(row)

- <th> : 표의 제목 셀(header)

- <td> : 표의 데이터 셀
