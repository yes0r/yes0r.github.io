1. 배운 내용 정리



리버싱이란?

프로그램을 거꾸로 분석해서 내부 동작의 원리와 구조를 알아내는 것이다.

즉, 만드는 과정을 리버스해서 따라가는 것!







리버싱에는 정적 분서과 동적 분석 있는데,



정적분석은 실행하지 않고 겉모습을 분석해 파일 종류, 크기, 내부 코드 구조 등을 확인하는 것이고,

안전한 대신 난독화 되면 어려워진다.



동적 분석은 실행해 동작을 분석하는 것으로 어떤 파일을 생성하는지나 레지스트리 변경, 함수 흐름 등을 볼 수 있어 실제 행동이 확인 가능하지만 분석환경이 필요하고, 안티디버깅 우회가 필요할 수 있게 된다.



'



프로그램이 저장될 때 0, 1 형태로 저장되게 되는데, 이 실행 파일을 바이너리라고 부른다.



컴파일러 동작 과정은 전처리, 컴파일, 어셈블, 링크로 이루어진다.





전처리는 주석을 제거하고, 매크로로 치환하는 것이고, 컴파일은 C언어를 어셈블리어로 번역하는 것, 어셈블은 컴파일로 생선되어진 어셈블리어 코드를 기계어로 변환하는 과정, 링크는 여러 목적 파일들을 연결하여 실행 가능한 바이너리로 만드는 과정이다.





디스 어셈블과 디컴파일에 대해 알아야 하는데,

디스 어셈블은 기계어 코드를 어셈블리어로, 디컴파일은 디스어셈블한 코드를 C와 같은 고급 언어로 재번역하는 것이다.









핵심 명령어는





데이터 이동: mov, lea

산술 연산: inc, dec, add, sub

논리 연산: and, or, xor, not

비교: cmp, test

분기: jmp, je, jg

스택" push, pop

프로시져: call, ret, leave

시스템콜: syscall



이다!



피연산자에는 총 3가지 종류가 올 수 있는데 상수, 레지스터, 메모리로 나뉜다. 메모리 피연산자는 []로 둘러싸인 것으로 표현되며, 앞에 지정자 TYPE PTR이 추가될 수가 있다



프로그램에는 프로그램 실행 시 가장 먼저 시작되는 주소인 Entry Point (EP)가 있다!

 correct로 필터링하면 뜨는데, 이 부근에서 찾아보면 된다.

눌러보고 근처를 확인해보면



![](/assets/img/posts/tistory/tistory-23-07.png)



이렇게 전체 흐름을 볼 수 있다. input을 출력하고, 입력을 받은 후 test 위, call 주소에 있는 함수에서 입력된 스트링과 저장된 스트링을 비교. 만약 둘이 같으면 어떤 숫자를 eax에 리턴하고, 다르면 0을 리턴하는데, 비트연산에서 and 연산을 할 시, 0끼리 더해야하지만 0이 나온다.

test 밑에 있는 je 명령은 우리가 배웠듯이 jump if 0이라 0이 나오면 뒤에 주소로 '점프'하라는 뜻이라서 0이 나오면 wrong을 출력하는 줄로 점프를 하게 된다.



그러니, 핵심인 줄은 입력값 검증 함수인 call cha110.7FF7C9651000이 되는데, 이유는 해당 함수에서 사요앚가 입력한 문자열과 내부 저장된 문자열을 비교해서 결과를 리턴하기 때문이다(eax에) 그러니 이 반환값에 따라 correct와 wrong 출력이 결정되니까 우리는 이 함수를 뜯어봐야만 한다.



![](/assets/img/posts/tistory/tistory-23-08.png)



들어가보면 lea rcx, [7FF7C9652220]로 Compar3_the_string를 로드하고, mov rdx, [rsp+40]을 통해 사용자 입력값을 로드한 후 call을 통해 둘이 strcmp로비교하고 test로 결과를 확인하게 된다. 그러므로, Compar3_the_str1ng랑 비교한다는 것을 확인할 수가있게 된다.



mov rdx, [rsp+40]가 사용자 입력값 로드라고 해석되는 이유는, x64 calling convention에서 함수 인자 전달 순서가 rcx → rdx → r8 → r9 순이기 때문이다. strcmp(str1, str2) 호출할 때



- rcx = 첫 번째 인자 = Compar3_the_str1ng로 저장되어있던 문자열이고

- rdx = 두 번째 인자 = 사용자 입력값인데



아까 메인 흐름에서



lea rcx, [rsp+20] 로 입력받은 값을 rcx에 넣고, call chall0.7FF7C9651000 로 비교 함수를 호출했기 때문에 함수 호충할때 입력값을 rsp+20에 저장 후 비교 함수 내부에서 스택 프레임이 바뀌면서 rsp+40위치로 이동되었다고 보면 된다.



따라서 correct를 출력하는 입력값은 저장되어있던 문자열인 Compar3_the_str1ng이 된다.
