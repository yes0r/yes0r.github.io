1. 배운 내용 정리



바이트 오더링

= 데이터를 저장하는 방식. 빅 엔디언(Big Endian)과 리틀 엔디언(Little Endian)이 있다.



이중 리틀 에디언 방식은 데이터를 저장할 때 역순으로 저장해 바이트의 순서가 뒤집어져있고, (바이트 자체는 정상적인

순서로 저장한다.) 빅 에디언은 사람이 보는 방식과 같게 정상적인 순서로 저장된다.



![](/assets/img/posts/tistory/tistory-26-01.png)

&lt;figcaption&gt;(자료) 수업자료 안의 설명표&lt;/figcaption&gt;



빅 에디언은 사람이 보기에 직관적이며, 대형 UNIX 서버에 사용되는 RISC 계열의 CPU에서 많이 사용이 되고 네트워크 프로토콜에 빅 엔디언이 사용된다는 장점이 있다. 애플리케이션 개발에 사용된 데이터를 네트워크로 송수신할 때 엔디언 타입을 변경해야 하기 때문이다.



리틀에디언은, 산술 연산과 데이터의 타입 확장/축소될 때 더 효율적이며, Intel X86cpu에서 리틀 엔디언 방식을 사용한다.





컴퓨터 구조(폰 노이만 구조)



폰 노이만 구조는 현대 컴퓨터의 기본 구조를 설명하는 개념으로,
폰 노이만은 컴퓨터가 동작하기 위해 크게 연산, 제어, 저장 기능이 필요하다고 보았으며, 이를 기반으로 현재의 컴퓨터 구조가 만들어졌다.





![](/assets/img/posts/tistory/tistory-26-01.png)



폰 노이만 구조는 크게 CPU, 기억장치(Memory), 버스(Bus)로 나누어 설명할 수 있는데, 각각 설명은 다음과 같다.







- CPU: 프로그램의 명령어를 실행하고 연산을 수행하는 중앙처리장치이며, CPU 내부에는 산술 논리 연산을 수행하는 ALU, 명령 실행을 제어하는 Control Unit, 데이터를 임시 저장하는 Register가 존재한다.



- 기억장치: 프로그램 코드와 데이터를 저장하는 공간이다. 컴퓨터는 필요한 데이터를 메모리에 저장하고 CPU가 이것을 읽어 실행한다.



- 버스: CPU와 메모리, 장치들 사이에서 데이터를 주고받는 통로 역할을 한다. 데이터 버스, 주소 버스, 제어 버스 등이 존재한다.









 IA-32, x86-64 ISA(Instruction Set Architecture)



ISA는 CPU가 이해하고 실행할 수 있는 명령어들의 집합 구조를 의미한다. 쉽게 말해 CPU와 프로그램 사이의 약속된 언어 체계라고 볼 수 있다. 대표적인 ISA에는 ARM, MIPS, AVR, x86/x64 등이 존재한다.





수업에서는 x86-64 아키텍처를 중심으로 학습하였ㅅ다. x86-64는 IA-32의 64비트 확장 아키텍처이며, 기존 32비트 환경과의 호환이 가능하다.



IA-32에서는 eax, ebx, ecx, edx 등의 32비트 레지스터를 사용하며, x86-64에서는 이를 확장한 rax, rbx, rcx, rdx 등의 64비트 레지스터를 사용한다.

x86-64 아키텍처는 고성능 프로세서 설계에 사용되며, 주로 데스크톱 환경에서 많이 사용된다. 또한 CPU 내부의 레지스터를 활용하여 빠르게 데이터를 처리하고 연산을 수행한다





레지스터



레지스터는 CPU 내부의 저장장치로, CPU가 빠르게 접근하여 사용할 수 있는 공간이다. CPU는 매우 빠른 속도로 연산을 수행하기 때문에 데이터를 빠르게 교환할 수 있는 저장 공간이 필요하며, 이를 위해 레지스터를 사용한다.



레지스터는 크게 범용 레지스터, 세그먼트 레지스터, 명령어 포인터 레지스터, 플래그 레지스터로 나뉜다



- 범용 레지스터: 연산이나 데이터 저장 등 다양한 용도로 사용되는 레지스터이다. 대표적으로 eax, ebx, ecx, edx 등이 있으며, x86-64 환경에서는 rax, rbx, rcx, rdx 등으로 확장되었다.



![](/assets/img/posts/tistory/tistory-26-02.png)

&lt;figcaption&gt;범용 레지스터들의 주요 용도&lt;/figcaption&gt;









- 세크먼트 레지스터: IA-32의 메모리 관리 모델에서 나오는 용어이다.

x86-64 아키텍처 이전에는 cs, ss, ds, es, fs, gs 총 6가지 세그먼트 레지스터가 존재하며, 각 레지스터의 크기는 16비트이다.

x86-64 아키텍처 이후에는 cs, ds, ss 레지스터는 코드 영역과 데이터, 스택 메모리를 가리킬 때 사용하며, 나머지 레지스터는 운영체제 별로 용도를 결정한다. IA-32 보호모드에서 세그먼트는 메모리를 조각내어 각 조각마다 시작주소, 범위, 접근 권한 등을 부여하여 메모리를 보호하는 기법을 의미한다.



![](/assets/img/posts/tistory/tistory-26-03.png)

&lt;figcaption&gt;IA-32 세그먼트 레지스터&lt;/figcaption&gt;





x86-64 아키텍처 이후로는 cs, ds, ss 레지스터는 코드 영역과 데이터, 스택 메모리를 가리킬 때 사용흐고, 나머지 레지스터는 운영체제 별로 용도를 결정한다.







- 명령어 포인터 레지스터: CPU가 어느 부분의 코드를 실행할지 가리키는 역할. x64 아키텍처의 명령어 레지스터는 rip이며, 크기는 8바이트이다.

한 줄씩 봐보면

```
mov dl, BYTE PTR[rsi+rcx]
```



로 rsi + rcx 주소에 있는 1바이트 값을 dl에 가져온다. 처음에는 rsi = 0x400000, rcx = 0이니까 0x400000 주소의 0x67을 가져오게게 된다.



그 다음으로

```
xor dl, 0x30
```

를 통해서, dl에 들어온 값과 0x30을 XOR한다. XOR은 같으면 0을, 다르면 1이 되는 연산법이기 때문에 0x30와 비트로 연산을 해본 다음에 아스키로 추측해보면 되는 것이다. 예를 들어 첫 값은 0x67 XOR 0x30 = 0x57이고, ASCII로 W가 된다.



0x67 = 0110 0111
0x30 = 0011 0000



해서



0110 0111
0011 0000
--------------
0101 0111



즉, 0x57 이렇게 계싼하는 식이다!



```
mov BYTE PTR[rsi+rcx], dl
```



그 뒤로 이 결과(xor한거)를 다시 원래 위치에 저장하게 된다. 그러니까, 0x400000에 원래 있던 0x67 대신 0x57를 저장하게 되는 것



```

```
