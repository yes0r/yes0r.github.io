```
from PIL import Image

def extract(img_path):
    img = Image.open(img_path).convert("RGB")
    bits = [c & 1 for r,g,b in img.getdata() for c in (r,g,b)]

    chars = []
    for i in range(0, len(bits)-7, 8):
        byte = int("".join(map(str, bits[i:i+8])), 2)
        if byte == 0:
            break
        chars.append(chr(byte))

    print("추출된 메시지:", "".join(chars))

extract("photo.png")
```

복습: LSB(Least Significant Bit)는 픽셀의 맨 끝 비트에 데이터를 숨기는 방식이라고 한다!





```
from PIL import Image

def embed(img_path, message, out_path):
    img = Image.open(img_path).convert("RGB")
    data = message.encode() + b"\x00"
    bits = [((b >> (7-i)) & 1) for b in data for i in range(8)]

    pixels = list(img.getdata())
    new_pixels = []
    bi = 0
    for r, g, b in pixels:
        if bi < len(bits): r = (r & 0xFE) | bits[bi]; bi += 1
        if bi < len(bits): g = (g & 0xFE) | bits[bi]; bi += 1
        if bi < len(bits): b = (b & 0xFE) | bits[bi]; bi += 1
        new_pixels.append((r, g, b))

    result = Image.new("RGB", img.size)
    result.putdata(new_pixels)
    result.save(out_path, "PNG")
    print("완료!")

embed("photo.jpg", "flag{I_like_you}", "photo.png")
```

가상머신으로 문제를 만드는 법





가상머신으로 포렌식 문제 만드는 기본 원리는 가상 환경 안에서 사용자의 행동이나 사건을 직접 재현하고,그 결과로 남은 흔적을 증거로 삼아서 문제를 만드는 것이다. 현실에서 일어날 법한 흔적은 vm 안에 일부러 만들어두고 그걸 분석하게 하는것!



전체 제작 순서는 보통 이러한 단계로 이루어진다고 한다.

- 가상머신 생성

- 운영체제 설치

- 문제에서 남길 행동 수행

- 필요한 흔적 정리

- 증거 수집

- 문제 파일 배포 형태로 가공

- 출제자 본인이 직접 검증





1단계인 가상머신 생성에서는,

포렌식 문제를 만들 때 실험용 컴퓨터 역할을 하는 가상머신을 쓰는 것인데



보통 VirtualBox나 VMware를 많이 쓴다고들 한다!

![](/assets/img/posts/tistory/tistory-21-23.png)



나에게도 함께 하고?... 있는 virualbox가 있다!



가상머신을 만들 때는 운영체제 종류, 디

![](/assets/img/posts/tistory/tistory-21-24.png)

스크 크기, 메모리 크기, 네트워크 사용 여부 등을 정하고 시작한다



보통은 Windows 포렌식 문제는 Windows 10/11을 많이 사용하고, Linux 포렌식 문제는 Ubuntu 계열을, 그 외 브라우저나 사용자, 파일 사용 흔적에 대한 문제는 윈도우가 만들기 쉽다고 한다!



처음 만들때 아무 흔적이 없는 깨끗한 상태에서 스냅샷을 하나 찍어두는 게 좋다고한다! 무언가 꼬였을 때 그 시점으로 되돌릴 수 있기 때문에!





2단계에선 운영체제를 설치하고 기본환경을 세팅하는데, OS 설치만 하고 바로 문제 만들기 시작하면 안 되고,
문제에서 필요한 기본 도구나 환경을 먼저 맞춰야한다고 한다.



예를 들면:

- 브라우저 설치

- 문서 작성 프로그램 설치

- 압축 프로그램 설치

- 테스트용 사용자 계정 생성

- 바탕화면/문서 폴더 구조 정리



등등을 해야만 분석을 할 때, 이 사용자가 크롬을 썼고 문서 작업을 했고 등등의 기록이 자연스럽게 보인다.



3단계가 사실상 핵심인데, 이 단계에선 사건을 vm 안에서 직접 재현을 해야한다.

특히 포렌식 문제는 파일을 하나 그냥 넣어두는게 아니라, 그 파일이 생기기까지의 행위를 vm 안에서 직접 해줘야 하기 때문에



파일 다운로드, 특정 문서 열기, 브라우저 검색, 압축 해제, 계정 로그인, 이미지 열람 등등 실제 행동을 해주게 되면 시스템에 흔적이 남게 된다! 이렇게 되면 최근 실행 목록이라던가 브라우저 히스토리, 다운로드 기록, 이벤트 로그 등등의 행동 흔적들이 남기 때문에 정답이 파일 안에만 있는 것이 아닌, 행동 흔적 전체에 퍼져있게 된다!





어떤 아티팩트를 남길지 먼저 흔적을 정하고 행동해야 하는데, 문제를 만들때 가장 중요하게 여겨야하는 것은 내가 어떤 흔적을 보이게 할지를 생각하는 것이다.



포렌식 문제는 주로 아티팩트 중심으로 만들기 때문에 예를 들어 파일 포렌식이면 삭제된 파일, 확장자 위장 파일, 메타데이터라던가 윈도우 사용 흔적으로 하면 Prefetc, Registry. 브라우저 포렌식이라면 기록들이나 흔적, 메모리 포렌식이라면 실행 중 프로세스와 커맨드 라인, 로그 분석이라면 웹 서버 로그, 시스템 이벤트 로그 등 다양한 아티팩트 중에서 내가 어떤 흔적을 남겨 보이게 할건지를 생각해봐야한다!





그리고, 또다른 중요한 점은 자연스러운 행동이다. 문제를 만드는 사람이 티 나게 흔적을 심으면 분석자가 보기에도 부자연스러워 보이기 때문에, 보통은 필요한 행동 말고도 불필요한 행동(일반 사이트 방문이나 문서 열기, 검색어 여러개 사용 등)들도 섞어준다!







문제를 다 만들었으면, 증거를 뽑아야한다. 가상머신 안에 있는 데이터를 분석 가능한 형태로 만들어야 하는데



정석적으로 디스크 전체를 뽑는 방법과, 필요한 파일만 뽑는 방법, 메모리(RAM)만 뽑는 방법 등 다양한 방법으로 증거를 춫출할 수가 있다.



디스크 전체 이미지를 추출 하는 방법으로는VirtualBox 기준으로 VM 종료 후 vdi 파일 찾기를 그대로 문제로 줘도 괜찮고, VM 디스크(.vdi, .vmdk) 확보 후 FTK Imager 실행해서 "Create Disk Image"으로 포렌식 이미지로 변환 해 RAW, E01으로 배포해도 괜찮다고 한다.

![](/assets/img/posts/tistory/tistory-21-25.png)

![](/assets/img/posts/tistory/tistory-21-26.png)



다음으로 필요한 파일만 추출하는 방법으로는 전체 디스크 말고, 핵심 증거만 뽑아서 제공하는 것인데

VM안에서 필요한 파일을 찾아 공유 폴더나 USB 등으로 복사해 직접 복사하거나, 분석 툴로 추출해 특정 파일만 export하는 방법 등이 있다.





증거를 뽑을 때는 언제 추출하느냐가 굉장히 중요한데, 시점에 따라 증거가 완전 달라질 수 있기때문에 이 점을 특히 유의해야만 한다. 또, 추출 후에는 검증이 필수다(다른 컴퓨터에서도 정답이 나오는지!). 출제자 흔적을 제거하는 것도 굉장히 중요하다.





출제자 검증은 반드시 해야하는 것이, 문제를 만들고 나면 꼭 풀어봐야한다. 가능하면 제작할 때 사용한 도구 말고 다른 도구로도 검증하면 좋은데 정답이 실제로 나오는지, 힌트가 너무 부족하진 않은지, 아니면 뭐 추측을 하는 흐름이 자연스럽게 될지 등등을 확인해보아야 하고, 파일 손상이나 시간 정보가 이상한 것도 발견하려면 출제자가 꼭!! 풀어봐야한다. 그러므로 검증은 반드시 필수!!
