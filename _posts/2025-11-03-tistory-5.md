3. app.route("/veln")에서는 request.args.get("param", "")라는 코드가 있는데, 이 코드는URL의 쿼리(?param=값)에서 param이라는 이름의 값을 꺼내서 param 변수에 넣고, 값이 없으면 빈 문자열 ""을 넣는 코드이다.

4. 다음으로 이 코드에서는 ,

url 변수가 param 값을 URL 쿼리 파라미터로 포함하는 URL을 생성하고

urllib.parse.quote(param)를 통해 param 값을 쿼리 파라미터로 안전하게 전달하도록 한다.

![](/assets/img/posts/tistory/tistory-5-06.png)



5. 이 코드는 GET이면 입력 폼 보여주고, POST로 입력 받으면 그 값을 검사(check_xss)해서 안전하면 "good" 팝업, 안전하지 않으면 "wrong" 팝업을 보여주고 이전 페이지로 되돌리는 코드이다.

![](/assets/img/posts/tistory/tistory-5-07.png)



6.이 문제는 쿠키를 이용하는 문제인데, flag에서 쿠키를 탈취하기 위한 param을 전달한 뒤 탈취한 쿠키를 memo 페이지에서 보이게 해주면 플래그를 얻을 수 있ㄱ게된다.



![](/assets/img/posts/tistory/tistory-5-08.png)

(브라우저가 document.cookie를 통해 쿠키를 읽어서 /memo?memo=사용자의쿠키값 형태의 URL로 이동한다. 그 결과 사용자의 쿠키 값이 쿼리 파라미터로 서버에 전송되어 서버에 노출되게된다.)

2. 코드를 보고, 그 전 코드와 달리 vuln 코드에서도 render_template을 사용하고 있다. 그래서, 지피티에게 render_template이 무엇인지 다시 한번 물어보고 정의를 써보겠다.



render_template는

HTML 파일 안의 빈칸(변하는 값) 을 파이썬에서 보내준 값으로 채워서,
그걸 화면에 보여주는 도구

&lt;h4 data-end=&quot;413&quot; data-start=&quot;406&quot; data-ke-size=&quot;size20&quot;&gt;즉:&lt;/h4&gt;

파이썬 → 값 만들어서 → render_template → HTML에 넣어서 → 웹페이지로 보여줌



이라는 것이다.



예시를 들어보자면...



&lt;h4 data-end=&quot;520&quot; data-start=&quot;494&quot; data-ke-size=&quot;size20&quot;&gt;1) Python 코드 (app.py)&lt;/h4&gt;

```
from flask import Flask, render_template
app = Flask(__name__)
@app.route("/")
def hello(): name = "예슬"
return render_template("hello.html", username=name)​
```

&lt;h4 data-end=&quot;730&quot; data-start=&quot;702&quot; data-ke-size=&quot;size20&quot;&gt;2) HTML 파일 (hello.html)&lt;/h4&gt;



```
<h1>안녕하세요 {{ username }} 님!</h1>
```





파이썬에서 만든 변수 → render_template로 HTML에 전달 → HTML에서 {{ 변수명 }} 으로 사용하게 해주는 흐름이라고 일단 이해했다.





여기서 주의해야 할 점은, reder_template는 기본적으로 변수를 그 변수의 값을 그냥 글자 그대로 HTML에 채워 넣는 것이라는 것이다. 글자 그대로 넣는 것이기 때문에 &lt;script&gt;를 써서 넣으면 그대로 출력이 되게 된다 < 그러니 써서는 안됨!!









2. &lt;script&gt;를 쓸 수 없기 때문에 다른 방법을 찾아봐야한다... 그런데 마침

vuln 페이지를 개발자도구를 키고 살펴보면 아래와 같은 취약점을 발견할 수 있다.

```
&lt;script&gt;
    var x = new URLSearchParams(location.search);
    document.getElementById('vuln').innerHTML = x.get('param');
&lt;/script&gt;
```





여기서 우리가 사전에 조사했던! 과제에 대한 지식이 나오는데, innerHTML에 대한 개념이다.



innerHTML은 HTML 태그를 문자열이 아니라 실제 HTML 요소로 해석하기 때문에 innerHTML이 태그를 문자열이 아니라 실제 HTML 요소로 변환해 브라우저가 실행하게 된다.



그렇기 때문에 위험 요소가 될 수 있다는! 뜻이 된다.

그렇다면 답은

&lt;img src=&quot;XSS-2&quot; onerror=&quot;location.href=&#x27;/memo?memo=&#x27;+document.cookie&quot;&gt;

이유를 설명해보면, src로 코드를 넣으면 vuln 페이지에 XSS-2라는 src를 가진 이미지를 삽입하려 시도를 하게 된다.

하지만 그런 것은 없기 때문에! onerror(오류가 났을때 실행되는 코드)를 통해 memo가 가진 쿠키의 값을 탈취해서 나에게 보여주게 되는 것이다!
